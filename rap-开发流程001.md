# RAP 开发流程 001 — 从零开始

> 适合有 ABAP 开发经验、RAP 零基础的开发者

---

## 整体架构（5 个核心对象，按顺序建）

```
CDS Root View  ────>  CDS Projection View  ────>  Service Binding
   (数据模型)            (投影/字段限制)            (OData 服务暴露给 Fiori)
      │
      └──> Behavior Definition
              (事务 CRUD 逻辑)
```

---

## 简单例子：航班管理（Airplane Management）

一个列表页面，管理航空公司航班：创建、修改、删除、查看。

---

## 第一步：建数据库表

```cds
@EndUserText.label: 'Airplane'
@AbapCatalog.enhancement.category: #NOT_EXTENSIBLE
@AbapCatalog.tableCategory: #TRANSPARENT
@AbapCatalog.deliveryClass: #A
@AbapCatalog.dataMaintenance: #RESTRICTED

define table zrap_atrairp {

  key client   : abap.clnt not null;
  key airplaneid : abap.numc(8) not null;

  @Semantics.text: true
  name          : abap.char(30);

  @Semantics.amount.currencyCode: 'zrap_atrairp.currency_code'
  price         : abap.curr(10,2);

  currency_code : abap.cuky(5);
  description   : abap.string(0);

  created_by    : abp_creation_user;
  created_at    : abp_creation_tstmpl;
  last_changed_by : abp_locinst_lastchange_user;
  last_changed_at : abp_locinst_lastchange_tstmpl;
  locallastchangedat: abp_lastchange_tstmpl;

}
```

---

## 第二步：建 CDS Root View（数据模型）

```cds
@AccessControl.authorizationCheck: #NOT_REQUIRED
@EndUserText.label: 'Airplane Root View'
define root view entity ZRAP_I_AIRPLANE
  as select from zrap_atrairp
{
  key airplaneid       as AirplaneId,
      name             as AirplaneName,
      price            as Price,
      currency_code    as CurrencyCode,
      description      as AirplaneDescription,
      created_by       as CreatedBy,
      created_at       as CreatedAt,
      last_changed_by  as LastChangedBy,
      last_changed_at  as LastChangedAt,
      locallastchangedat as LastChanged
}
```

---

## 第三步：建 Behavior Definition（业务行为）

```abap
managed implementation in class zbp_rap_i_airplane unique;

strict(2);

define behavior for ZRAP_I_AIRPLANE
persistent table zrap_atrairp
lock master
authorization master ( instance )
etag master Locallastchangedat

{
  create;
  update;
  delete;

  field ( readonly ) AirplaneId, CreatedBy, CreatedAt, LastChangedBy, LastChangedAt, LastChanged;

  mapping for zrap_atrairp
  {
    AirplaneId          = airplaneid;
    AirplaneName        = name;
    Price               = price;
    CurrencyCode        = currency_code;
    AirplaneDescription = description;
    CreatedBy           = created_by;
    CreatedAt           = created_at;
    LastChangedBy       = last_changed_by;
    LastChangedAt       = last_changed_at;
    LastChanged         = locallastchangedat;
  }
}
```

要点：
- `managed`：RAP 自动处理 Create/Update/Delete（不用写 SQL）
- `mapping`：CDS 字段名（驼峰）映射到数据库字段名（下划线）
- `field (readonly)`：系统自动生成的值，禁止前端修改

---

## 第四步：建 Behavior Implementation 类（业务逻辑）

```abap
CLASS zbp_rap_i_airplane DEFINITION PUBLIC ABSTRACT FINAL FOR BEHAVIOR OF ZRAP_I_AIRPLANE.
ENDCLASS.

CLASS zbp_rap_i_airplane IMPLEMENTATION.

  METHOD get_instance_features.
    " 无特殊行为
  ENDMETHOD.

  METHOD validate_data.

    READ ENTITIES OF ZRAP_I_AIRPLANE IN LOCAL MODE
      ENTITY Airplane
      ALL FIELDS WITH
      CORRESPONDING #( keys )
    RESULT DATA(airplanes).

    LOOP AT airplanes INTO DATA(airplane).
      IF airplane-AirplaneName IS INITIAL.
        APPEND VALUE #( %tky = airplane-%tky )
          TO failed-airplane.
        APPEND VALUE #( %tky  = airplane-%tky
                        %msg  = new_message( id       = '00'
                                             number   = '001'
                                             severity = if_abap_behv_message=>severity-error
                                             v1       = 'Airplane name required' )
                        %element-AirplaneName = if_abap_behv=>mk-on )
          TO reported-airplane.
      ENDIF.
    ENDLOOP.

  ENDMETHOD.

ENDCLASS.
```

---

## 第五步：建 Projection View（投影层）

```cds
@AccessControl.authorizationCheck: #NOT_REQUIRED
@EndUserText.label: 'Airplane Projection'
define root view entity ZRAP_C_AIRPLANE
  provider contract transactional_query
  as projection on ZRAP_I_AIRPLANE
{
  key AirplaneId,
      AirplaneName,
      Price,
      CurrencyCode,
      AirplaneDescription,
      @Consumption.hidden: true
      LastChanged
}
```

Projection 下挂 Behavior Projection：

```abap
projection;
define behavior for ZRAP_C_AIRPLANE
{
  use create;
  use update;
  use delete;
}
```

---

## 第六步：建 Service Binding（暴露 OData）

在 ADT (Eclipse) 中右键 Projection View → **New Service Binding**：

- Binding Type: **OData V2 - UI** 或 **OData V4 - UI**
- Service Name: `ZUI_AIRPLANE_V2` 或自定义

Activate 后，点击 **Publish** → 生成 OData URL。

## 开发顺序总结

| 步骤 | 对象 | 干什么 |
|:---:|------|--------|
| 1 | 数据库表 `zrap_atrairp` | 建持久化表（或用已有表） |
| 2 | CDS Root View `ZRAP_I_AIRPLANE` | 基于表定义数据模型（不用写 SQL） |
| 3 | Behavior Definition | 定义 CRUD 操作、字段映射、锁机制 |
| 4 | Behavior Impl. Class | （可选）自定义校验、决定、动作 |
| 5 | Projection View `ZRAP_C_AIRPLANE` | 过滤字段，面向 UI |
| 6 | Service Binding | 绑定 OData 协议，发布服务 |
| 7 | Fiori App / SAPUI5 | 消费 OData 生成 UI |

## 对 ABAP 老手的快速理解

| 传统 ABAP | RAP |
|-----------|-----|
| SE11 View + SELECT | CDS View |
| 手工 INSERT/UPDATE/DELETE + BOPF | Behavior Definition (Managed) |
| SEGW Gateway Builder 配 OData | Service Binding |
| `SELECT * FROM dbtab INTO TABLE ...` | `READ ENTITIES ... ALL FIELDS WITH` |

## EML 详解：READ ENTITIES

```abap
READ ENTITIES OF ZRAP_I_AIRPLANE IN LOCAL MODE
  ENTITY Airplane
  ALL FIELDS WITH CORRESPONDING #( keys )
  RESULT DATA(airplanes).
```

### 逐段解释

| 语法 | 含义 |
|------|------|
| `READ ENTITIES OF ZRAP_I_AIRPLANE` | 从指定的 RAP BO 读数据 |
| `IN LOCAL MODE` | 在行为实现类内部使用，跳过权限，直接访问事务 buffer |
| `ENTITY Airplane` | 操作 BO 里的哪个实体（BDEF 中 alias 定义） |
| `ALL FIELDS WITH ...` | 读所有字段；可替换为 `FIELDS ( f1 f2 ) WITH ...` |
| `CORRESPONDING #( keys )` | 把 keys 内表映射到 READ IMPORT 参数结构 |

### 参数流向

```
前端/Fiori 发送 OData 请求
         │
         ▼
RAP 框架把请求转成 keys 内表 (TYPE TABLE FOR READ IMPORT)
  每条记录 = { %tky-AirplaneId = 'xxx' }
         │
         ▼
validate_data 方法收到 keys 参数
         │
         ▼
READ ENTITIES ... CORRESPONDING #( keys )   ← 用 keys 指定要读的行
         │
         ▼
框架从 buffer 中查出对应数据
         │
         ▼
airplanes 内表 (TYPE TABLE FOR READ RESULT)
  每条记录 = { %tky-... + 所有业务字段 }
         │
         ▼
LOOP AT airplanes ... 逐条校验
```

### %tky（Transient Key）

`%tky` 是 RAP 的核心概念——每条实体在事务 buffer 中的唯一标识。它不直接等于数据库主键，而是框架维护的"临时句柄"：

```abap
" keys 的结构（概念上）:
keys = [ { %tky-AirplaneId = '00000001' },
         { %tky-AirplaneId = '00000002' } ]

" 读取结果:
airplanes = [
  { %tky-AirplaneId = '00000001', AirplaneName = 'A380', Price = '500.00', ... },
  { %tky-AirplaneId = '00000002', AirplaneName = 'B747', Price = '400.00', ... }
]
```
